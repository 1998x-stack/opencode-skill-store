01 · 架构决策

将 Skill Store 变成 OpenCode 原生 Skills 页面的一部分，而不是把一个独立网站嵌进 OpenCode。

关键边界：浏览器只传 asset_id、version 和 idempotency_key。API Key、下载、SHA 校验、解压、磁盘写入和 Runtime 注册都留在 OpenCode Server。
原生 UI扩展已有 Skills subtab，不新增 iframe、外部壳站或重复导航。
复用 Runtime通过 Server Plugin 的 Skill transform API 注入，不再造第二套 Skill loader。
事务安装版本目录不可变，active.json 原子切换，失败恢复旧版本。
Location 隔离安装状态属于当前 OpenCode Location，不跨项目泄漏。

02 · OpenCode Web 原生接入

源码审计发现当前 Fork 已有 Settings → Extensions → Skills。现有页面从 Location Skill Registry 读取 Skill 列表，因此本方案扩展它，而不是再加一条 /skills 路由。

模块修改职责
settings/providers/extensions.tsx在已有 Skills 列表后嵌入 Store 面板。
settings/providers/skill-store.tsxDiscover、Installed、搜索、详情、安装、更新、启停、卸载和操作进度。
settings/providers/skill-store-rpc.ts定义 Web Client 使用的 JSON Schema RPC Contract。
runtime/i18n/en.ts集中维护 UI 文案。

当前 Server Client

const rpc = () => serverSdk.api.rpc(SkillStoreRPC)
const result = await rpc().catalogSearch({ query, limit: 24 })

不要长期缓存旧 SDK Client。Server reconnect 时 API transport 可能变化。RPC 事件带 location，前端按 event.location.directory 过滤。

04 · Typed RPC

Method用途
catalogSearch / catalogDetail目录搜索和详情。
installationList当前 Location 安装列表。
operationList / operationGet页面刷新和断线恢复。
installStart / operationCancel异步安装或更新、显式取消。
installationSetEnabled / installationPin启停与版本固定。
installationUninstall / updateCheck卸载和更新检查。
RPC events 是 live-only。持久化 operation 状态才是事实来源；刷新页面后重新调用 operationList 和 installationList。

06 · Skill Package 契约

skill-package.zip
├── SKILL.md
├── references/
├── scripts/
├── assets/
└── examples/

ZIP 根目录直接包含非空 SKILL.md。Supporting files 保留相对目录。Runtime ID 使用稳定 Store namespace：ss-<asset-slug>-<hash>。

Runtime Info 由 id、name、description、autoinvoke、absolute SKILL.md path 和 Markdown body 组成。插件调用 ctx.skill.transform() 注册，外部状态变化后调用 ctx.skill.reload()。

07 · 安装事务

  1. Resolve：获取资产详情、目标版本和 package metadata。
  2. Download：流式写入 staging，同时计算 SHA-256 和字节数。
  3. Verify：摘要、长度、平台、架构和包结构校验。
  4. Extract：拒绝不安全 entry，解压到 staging/content。
  5. Commit：写不可变 versions/<version>，原子切换 active.json。
  6. Register：ctx.skill.reload()，再用 ctx.skill.list() 验证。
  7. Complete：持久化 operation=installed，发送进度事件。
Runtime 注册失败时恢复旧 active.json 和旧安装记录。旧版本不能在新版本验证前删除。相同 asset/version 对应不同 SHA 必须拒绝。

08 · ZIP 与供应链安全

  • 拒绝绝对路径、..、反斜杠、盘符、UNC、NUL、冒号路径段和 Windows 保留设备名。
  • 拒绝符号链接、硬链接和特殊文件。
  • 拒绝重复 entry、大小写冲突、ZIP Bomb 和超限文件。
  • 只写入 staging，限制包大小、解压总量、entry 数和压缩比。
  • 不保留 setuid/setgid，不在安装时执行 scripts。
  • 卸载前验证路径仍在本插件 installRoot 内。

SHA-256 只能验证字节完整性；发布者身份认证需要后续签名 manifest 和可信公钥。

09 · Location 隔离

当前 OpenCode Plugin 的 ctx.location 表示插件实例加载的 Location。安装目录 hash 使用 directory 与可选 workspaceID。注意：Host 的 ctx.storage 只按 plugin ID 建立 namespace，不会自动隔离 Location。

因此文件目录和 durable state 都必须使用同一个显式 Location hash；ctx.storage key 采用 location:v1:<hash>: 前缀：

$OPENCODE_SKILL_STORE_DIR/<location-hash>/
  skills/<runtime-id>/
    active.json
    versions/<version>/SKILL.md
  staging/<operation-id>/

Server 和 Location 是两个维度。相同 Server 的不同项目也可能有不同安装状态。持久化 key 同样按 Location 隔离；真正 Server-global 共享需要显式 scope、全局锁和跨 Location reload 通知，不可简单共享一个目录。

11 · 本地部署

# OpenCode Fork
bun install
bun run check
bun run dev --port 4096

# Web
bun run dev:web

# Plugin
cd packages/opencode-skill-store-plugin
bun install
bun test
bun run typecheck

在 OpenCode Server 进程设置 SKILL_STORE_BASE_URL、SKILL_STORE_API_KEY。把本地 Plugin 路径添加到 opencode.jsonc，重启 Server 后打开 Settings → Extensions → Skills。
